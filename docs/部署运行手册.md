# 部署运行手册

> 目标：单台 Linux 服务器，Docker Compose 运行 1 个 app 容器，SQLite 持久化。HTTPS 由现有反向代理终止，证书不放进 app 容器。

> [!IMPORTANT]
> 只能运行 1 个 `app` 副本。房间、余额和 WebSocket 都在单进程内，SQLite 不支持水平扩容。

---

## 1. 服务器要求

- Ubuntu 22.04 / 24.04 或其他 Docker 可用的 Linux
- 架构：`linux/amd64` 或 `linux/arm64`
- Docker Engine 24+，Compose v2
- 1 vCPU / 1 GB 内存 / 10 GB 磁盘起
- 入站端口：由反向代理决定；不使用代理时放行 `3000`
- 出站：能拉取 `ghcr.io/shanggui/monopay:v0.1.1`

镜像同时提供 amd64 / arm64，公开镜像不需要 `docker login`。

---

## 2. 首次部署

```bash
mkdir -p /opt/monopay/{data,backups}
cd /opt/monopay

cp /path/to/Monopay/deploy/compose.yaml ./compose.yaml
cp /path/to/Monopay/deploy/.env.example ./.env

sudo chown -R 1000:1000 data backups
```

编辑 `.env`：

```dotenv
PUBLIC_URL=https://monopay.example.com
BIND_ADDR=127.0.0.1
APP_PORT=3000
TRUST_PROXY=true
MONOPAY_IMAGE=ghcr.io/shanggui/monopay
MONOPAY_TAG=v0.1.1
LOG_LEVEL=info
```

启动：

```bash
docker compose pull
docker compose up -d --wait
docker compose ps
```

本机验证：

```bash
curl -fsS http://127.0.0.1:3000/healthz
curl -fsS http://127.0.0.1:3000/readyz
```

预期 `healthz`、`readyz` 都是 200，`readyz.data.database` 为 `ok`。

## 3. 反向代理与 HTTPS（可选）

### 已有 Nginx / Traefik

- 应用只监听 `127.0.0.1:3000`
- 反向代理终止 TLS，证书挂在反向代理层
- 转发到 `http://127.0.0.1:3000`
- `.env` 设置：

```dotenv
PUBLIC_URL=https://monopay.example.com
BIND_ADDR=127.0.0.1
TRUST_PROXY=true
```

Nginx 关键配置：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

WebSocket 必须保留 `Upgrade` / `Connection`，否则到账提示会断。

### 没有反向代理

直接使用 IP + HTTP：

```dotenv
PUBLIC_URL=http://203.0.113.10:3000
BIND_ADDR=0.0.0.0
TRUST_PROXY=false
```

```bash
docker compose up -d --wait
```

放行防火墙 `3000`，访问 `http://203.0.113.10:3000`。这不是 HTTPS 生产验收，仅适合局域网或临时验证。

### 不建议

不要把证书挂进 app 容器。app 只提供 HTTP 3000；TLS 终止层（Nginx/Traefik/云负载均衡）负责证书和 443。

## 4. 数据目录

```text
/opt/monopay/
  compose.yaml
  .env
  data/monopay.db        # SQLite
  backups/               # 备份
```

容器以 UID 1000 的 node 用户运行，`data/`、`backups/` 必须可写：

```bash
sudo chown -R 1000:1000 /opt/monopay/data /opt/monopay/backups
```

不要删除 `data/`；删除等于清空所有房间和流水。

---

## 5. 每日备份

```bash
cd /opt/monopay
docker compose exec app node scripts/backup.mjs
ls -lh backups/
```

脚本使用 SQLite Online Backup API，不停机；默认保留 7 天。

cron 示例：

```cron
15 3 * * * cd /opt/monopay && docker compose exec -T app node scripts/backup.mjs >> backups/backup.log 2>&1
```

备份必须复制到另一块盘/对象存储；只留本机不算备份。

---

## 6. 恢复

先停 app，避免继续写入：

```bash
cd /opt/monopay
docker compose stop app
```

恢复到一个临时文件验证：

```bash
docker compose run --rm --no-deps \
  app node scripts/restore.mjs /backup/monopay-YYYY....db /data/monopay-restored.db --force
```

用临时文件启动验证（不要覆盖正式库）：

```bash
docker compose run --rm --no-deps \
  -e DB_PATH=/data/monopay-restored.db -p 3001:3000 \
  app node dist/index.js
curl -fsS http://127.0.0.1:3001/readyz
```

确认后切换正式文件：

```bash
mv data/monopay.db data/monopay.db.before-restore
mv data/monopay-restored.db data/monopay.db
rm -f data/monopay.db-wal data/monopay.db-shm
docker compose start app
curl -fsS http://127.0.0.1:3000/readyz
```

记录恢复日期、备份文件、验证结果。

## 7. 升级与回滚

升级：

```bash
cd /opt/monopay
docker compose exec app node scripts/backup.mjs
# 修改 .env 的 MONOPAY_TAG
docker compose pull
docker compose up -d --wait
```

回滚：

```bash
# 把 MONOPAY_TAG 改回旧版本
docker compose pull
docker compose up -d --wait
```

如果新版本迁移了数据库，回滚前先恢复旧版本备份；SQLite 迁移不自动降级。

## 8. 观测

```bash
docker compose ps
docker compose logs -f --tail=200 app
curl -fsS http://127.0.0.1:3000/healthz
curl -fsS http://127.0.0.1:3000/readyz
```

关注：

- `readyz` 非 200
- 磁盘剩余空间（SQLite + 备份）
- 容器重启次数
- 429 限流与 5xx
- 反向代理的 502/504 和证书续期

---

## 9. 安全

- CSP：`default-src 'self'`、`script-src 'self'`、`frame-ancestors 'none'`
- 创建/加入房间限流 30/分钟/IP；付款 1200/分钟/IP
- token 只以 SHA-256 hash 存库；Authorization 日志脱敏
- 生产环境必须用 HTTPS；无域名 HTTP 仅用于验证
- app 容器：非 root、只读根文件系统、`cap_drop: ALL`、`no-new-privileges`
- 不要公开 `.env`、`data/`、`backups/`

---

## 10. 故障处理

| 现象 | 处理 |
|---|---|
| `readyz` 503 | 看 app 日志、磁盘、`data/` 权限 |
| 端口被占用 | 改 `.env` 的 `APP_PORT`，同步改反代 |
| 502/504 | 检查反代目标是否为 `127.0.0.1:3000`，容器是否 healthy |
| WebSocket 断 | 检查反代 `Upgrade` / `Connection` 头 |
| 二维码地址错 | 改 `PUBLIC_URL` 为浏览器实际地址，重启 |
| 磁盘满 | 清理旧备份/日志；SQLite 写入会失败 |
| 备份失败 | 检查 `/backup` 权限和磁盘 |
