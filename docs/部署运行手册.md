# 部署运行手册

> 目标：单台 Linux 服务器，Docker Compose + Caddy 自动 HTTPS，SQLite 数据持久化。
>
> 重要：**只部署 1 个 app 副本**。房间、余额和 WebSocket 都在单进程内，不能水平扩容。

---

## 1. 服务器要求

- Ubuntu 22.04 / 24.04（或其他 Docker 可用的 Linux）
- 架构：`linux/amd64` 或 `linux/arm64`（v0.1.1 起 GHCR 镜像同时发布两种架构）
- Docker Engine 24+，Compose v2
- 域名 A/AAAA 记录指向服务器
- 入站 80/443；出站可访问 `ghcr.io`
- 建议 1 vCPU / 1 GB 内存 / 10 GB 磁盘；2 vCPU 更稳
- 已有反向代理时，不要再启动本 Compose 的 Caddy，改为代理到 `127.0.0.1:3000`

---

## 2. 首次部署

```bash
sudo mkdir -p /opt/monopay
cd /opt/monopay
```

把仓库的 `deploy/` 目录内容放到服务器，至少：

```text
compose.yaml
Caddyfile
deploy.sh
smoke.sh
.env
```

`deploy.sh` 会检查 env、拉镜像、等待健康检查并跑 smoke test：

```bash
chmod +x deploy.sh smoke.sh
./deploy.sh
```

创建 `.env`：

```bash
cp .env.example .env
```

编辑：

```dotenv
DOMAIN=monopay.example.com
PUBLIC_URL=https://monopay.example.com
MONOPAY_IMAGE=ghcr.io/shanggui/monopay
MONOPAY_TAG=v0.1.1
LOG_LEVEL=info
```

登录 GHCR（私有镜像时需要）：

```bash
echo "$GHCR_TOKEN" | docker login ghcr.io -u <github-user> --password-stdin
```

启动：

```bash
docker compose pull
docker compose up -d
docker compose ps
```

验证：

```bash
curl -fsS https://monopay.example.com/healthz
curl -fsS https://monopay.example.com/readyz
curl -fsSI https://monopay.example.com/ | head
```

预期：

- `healthz` 200，`readyz` 200，`database: ok`
- 首页 200，CSP/HSTS 存在
- 浏览器可创建房间、扫码加入、付款

### 没有域名：IP + HTTP

如果没有域名，用 `compose.ip.yaml`，不启动 Caddy：

```bash
mkdir -p /opt/monopay/{data,backups}
cd /opt/monopay
cp /path/to/deploy/compose.ip.yaml compose.yaml
cp /path/to/deploy/.env.ip.example .env
# 编辑 .env：PUBLIC_URL=http://<服务器公网或局域网IP>:3000
docker compose up -d --wait
```

访问 `http://<IP>:3000`。这能完成功能 smoke test，但不是 HTTPS 生产验收；公网使用请尽快补域名/免费 DDNS 子域名。若 80/443 已被现有 Nginx 占用，把 app 改成 `ports: ["127.0.0.1:3000:3000"]`，由现有 Nginx 反代。

## 3. 数据与目录

```text
/opt/monopay/
  compose.yaml
  Caddyfile
  .env
  data/monopay.db        # SQLite（WAL/SHM 同目录）
  backups/               # 备份
```

Compose 已设置：

- app 非 root 运行
- `read_only` 根文件系统，仅 `/data`、`/backup`、`/tmp` 可写
- `cap_drop: ALL`
- `no-new-privileges`
- 日志 max 10 MB × 3

---

## 4. 每日备份

应用镜像内包含备份脚本：

```bash
cd /opt/monopay
docker compose exec app node scripts/backup.mjs
ls -lh backups/
```

脚本使用 SQLite Online Backup API，不需要停机；默认保留 7 天。

推荐 cron（每天 03:15）：

```cron
15 3 * * * cd /opt/monopay && docker compose exec -T app node scripts/backup.mjs >> backups/backup.log 2>&1
```

备份目录也要异地/对象存储复制一份；只留在同一块盘不算备份。

## 5. 恢复演练

1. 先停 app，避免继续写入：

```bash
cd /opt/monopay
docker compose stop app
```

2. 选一个备份，恢复到一个新文件先验证：

```bash
docker compose run --rm --no-deps \
  -e DB_PATH=/data/monopay.db \
  app node scripts/restore.mjs /backup/monopay-YYYY....db /data/monopay-restored.db --force
```

3. 用恢复文件启动临时实例：

```bash
docker compose run --rm --no-deps \
  -e DB_PATH=/data/monopay-restored.db -e PORT=3000 -p 3001:3000 \
  app node dist/index.js
curl -fsS http://127.0.0.1:3001/readyz
```

4. 确认房间、流水可读后，切回正式文件：

```bash
mv data/monopay.db data/monopay.db.before-restore
mv data/monopay-restored.db data/monopay.db
rm -f data/monopay.db-wal data/monopay.db-shm
docker compose start app
curl -fsS https://monopay.example.com/readyz
```

每次恢复演练记录日期、备份文件、校验结果。

## 6. 升级与回滚

升级：

```bash
cd /opt/monopay
# 先备份
docker compose exec app node scripts/backup.mjs
# 改 .env 的 MONOPAY_TAG
docker compose pull
docker compose up -d
curl -fsS https://monopay.example.com/readyz
```

回滚：

```bash
# 把 MONOPAY_TAG 改回上一个 tag
docker compose pull
docker compose up -d
```

若新版本迁移了数据库，回滚前先恢复对应版本备份；SQLite 迁移不做自动降级。

## 7. 观测

```bash
docker compose ps
docker compose logs -f --tail=200 app
docker compose logs -f --tail=200 caddy
curl -fsS https://monopay.example.com/healthz
curl -fsS https://monopay.example.com/readyz
```

关注：

- `readyz` 非 200
- 磁盘剩余空间（SQLite + 备份）
- Caddy 证书续期日志
- 5xx 与 rate-limit 429
- 容器重启次数

---

## 8. 安全

- CSP：`default-src 'self'`、`script-src 'self'`、`frame-ancestors 'none'`
- HSTS 由 Caddy/Helmet 下发
- 创建/加入房间限流 30/分钟/IP；付款限流 1200/分钟/IP
- token 只以 SHA-256 hash 存库；日志脱敏 Authorization
- 不要公开 `.env`、`data/`、`backups/`
- 单副本；不要加 `deploy.replicas > 1`

---

## 9. 故障处理

| 现象 | 处理 |
|---|---|
| `readyz` 503 | 看 app 日志、磁盘、DB 文件权限 |
| 502/504 | `docker compose ps`，Caddy 到 app 健康状态 |
| 证书失败 | 检查 80/443、DNS、Caddy 日志 |
| 磁盘满 | 清理旧备份/日志；SQLite 写入会失败 |
| 房间打不开 | 确认没有多副本；确认 `PUBLIC_URL` 与域名一致 |
| 备份失败 | 检查 `/backup` 权限与磁盘；备份不能只留一份 |
