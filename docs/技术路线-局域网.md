# Monopay 技术路线 v2：局域网 Host（零云费）

> 历史方案：已被 v3.0 Web + 自有服务器取代；保留为参考/备选。
>
> 版本：v2.0 ｜ 日期：2026-11-02 ｜ 对应产品设计 v2.0
>
> 前提：房主设备跑 **Host App** 当服务器；玩家用微信小程序通过 **LAN TCP** 加入；房主必须是非 iPhone；iPhone 只能加入，不能开房。
>
> **Gate 0**：先验证 `wx.createTCPSocket` 在 iOS/Android 体验版可用。不通过就回退浏览器客户端或云开发，不进入全量开发。

---

## 0. 结论先行

- **零云费**：房间、账本、结算全在房主设备的 Host App 里；不走云开发。
- **Host App**：Android 手机/平板（主）、笔记本/平板（备）；iPhone 不做 Host。
- **玩家端**：微信小程序；扫码/输 IP 加入；iPhone/Android 都可以当玩家。
- **协议**：TCP + NDJSON（一行一个 JSON）；Host App 是唯一权威；SQLite 持久化。
- **实时**：Host App 推事件；收款人本地响；其他玩家静默更新。
- **成本**：0 云费；代价是房主设备要跑 Host App、开热点/同 Wi-Fi、保持前台/充电。
- **开发**：先桌面 Host 做 spike/验证，再做 Android Host；总计约 8–12 周。

---

## 1. 硬约束

### 1.1 小程序不能当服务器

微信小程序没有稳定的 `listen` 能力：

- `wx.createTCPSocket` 是客户端，只能 `connect`，不能监听端口。
- 小程序不能常驻后台当房间服务。
- 所以“房主开小程序当服务器”不成立；房主必须跑 **Host App**。

### 1.2 `wx.createTCPSocket` 是 Gate

玩家小程序要连房主设备，只有两条路：

1. `wx.createTCPSocket` 连 `tcp://host-ip:port`（本路线）。
2. 回退到浏览器（Host App 同时提供 HTTP/WS）或云开发。

`wx.createTCPSocket` 的可用性、iOS 本地网络权限、审核限制，必须先用最小 demo 验证：

- iOS / Android 真机各一台；
- 体验版小程序；
- 连接笔记本上的 Node TCP 服务；
- 收发、断线重连、6 客户端并发、切后台/锁屏。

**Gate 0 不通过，不要做 Host App。**

### 1.3 房主必须非 iPhone

iPhone 上跑长期在线的本地 Host App 不实际：

- 后台会被系统挂起；
- 分发要 TestFlight/App Store；
- 热点/本地网络权限麻烦。

所以：

- **Android 手机/平板**：可以装 Host App。
- **笔记本/平板**：可以跑 Node/Electron Host，最稳。
- **iPhone**：只能当玩家；创建房间页提示“请用非 iPhone 设备开房间”。

### 1.4 网络前提

- 房主开热点，或所有人在同一个 Wi-Fi。
- 路由器/热点不能开 **AP 隔离**（客户端之间能互访）。
- 房主设备防火墙放行 Host 端口。
- 房主设备不能休眠/锁屏杀进程；需要前台服务 + 唤醒锁 + 充电。

## 2. 设备与角色

| 设备 | 角色 | 说明 |
|---|---|---|
| Android 手机/平板 | **Host App** | 开房间、跑 TCP 服务、SQLite、银行控制台、二维码 |
| 笔记本/平板 | **Host App**（Node/Electron） | 开发/试玩最稳；可选 |
| iPhone | **玩家小程序** | 只能加入；创建房间页提示换非 iPhone |
| Android 手机 | **玩家小程序** | 加入、付款、流水、结算 |
| 任意手机浏览器 | **玩家（回退）** | 如果小程序 LAN TCP 不可用；Host 提供 HTTP/WS |

> Host App 和玩家小程序是两个端。房主不需要用小程序开房；玩家不需要装 Host App。

## 3. 总体架构

```text
┌──────────────────── 房主设备（Android/平板/笔记本） ────────────────────┐
│  Monopay Host App                                                       │
│  ├─ TCP Server :3000        NDJSON 协议；玩家小程序连接                  │
│  ├─ HTTP/WS :8080           可选：浏览器玩家回退                         │
│  ├─ SQLite                  房间/玩家/流水/结算；单写者                   │
│  ├─ Host UI                 开房/银行/流水/结算                          │
│  └─ QR                      tcp://192.168.43.1:3000?room=ABC123          │
└──────────────────────────────┬──────────────────────────────────────────┘
                               │ 同一 Wi-Fi / 房主热点
┌──────────────────────────────▼──────────────────────────────────────────┐
│  玩家手机（iOS/Android）                                                 │
│  微信小程序                                                              │
│  ├─ wx.scanCode 扫码 / 手动输 IP                                         │
│  ├─ wx.createTCPSocket 连接 Host                                        │
│  ├─ 本地 playerToken（storage）                                          │
│  └─ 付款/流水/结算/音效                                                  │
└──────────────────────────────────────────────────────────────────────────┘
```

### 3.1 一次付款

```text
玩家点确认
  → 小程序通过 TCP 发 {type:'action', action:'playerPay', ...}
  → Host App 校验房间/成员/余额/幂等
  → SQLite BEGIN IMMEDIATE:
       扣付款方、加收款方、写 transactions、更新 seq
  → Host 广播 event 给房间内所有客户端
  → 收款人收到 event 播音效/横幅；其他人静默刷新
  → TCP ack 返回付款人
```

### 3.2 开房/加入

```text
房主打开 Host App
  → 选身份（银行-only/双身份）、初始资金、人数、工资
  → 启动 TCP 服务，生成 roomCode
  → 显示 IP/端口/房号 + 二维码

玩家打开小程序
  → 扫码 / 输 IP + 房号
  → wx.createTCPSocket 连接
  → hello/join（昵称、playerToken）
  → Host 返回 snapshot；进入大厅
```

## 4. Host App

### 4.1 形态选择

| 形态 | 优点 | 缺点 | 建议 |
|---|---|---|---|
| **Node/Electron 桌面 Host** | 复用 `ledger-core` TS；开发最快；调试方便 | 需要笔记本/平板；不够“手机-only” | **先做这个做 spike/试玩** |
| **Android 原生 Host** | 手机/平板可当 host；户外可用 | 开发量大；前台服务/热点/电池；两套代码 | 验证后做 |
| **Android + nodejs-mobile** | 复用 TS 核心 | 集成复杂、APK 大、生态少 | 不推荐首选 |
| **Flutter/React Native Host** | 跨端 UI | 内嵌 TCP 服务器仍要原生模块；核心逻辑要重写 | 不推荐首选 |

**推荐顺序**：

1. 先用 **Node/Electron 桌面 Host** 做 LAN TCP spike 和玩法验证。
2. 验证通过后，再做 **Android 原生 Host**；协议和 SQLite schema 不变。

### 4.2 Android Host 关键点

- Kotlin + Jetpack Compose（Host UI）。
- TCP Server：Ktor/Netty/Java ServerSocket 均可；单房间/多房间都用同一套。
- SQLite：Room 或 SQLiteOpenHelper；`BEGIN IMMEDIATE`；WAL。
- 前台服务：`foregroundServiceType`；通知“Monopay 房间运行中”；唤醒锁。
- 电池优化白名单引导；建议插电。
- 热点：引导用户手动开热点；显示当前 IP；不要假设能程序化开启。
- 二维码：生成 `tcp://ip:port?room=CODE`；屏幕常亮。
- 玩家列表/踢人/黑名单；最多 6 人。
- 数据导出：JSON/SQLite 备份；换机/重装用。

### 4.3 桌面 Host 关键点

- Node 18+；`net` 模块 TCP Server；`better-sqlite3`；`qrcode`。
- 可选 `express`/`ws` 提供浏览器回退。
- `npm start` 启动；终端和页面都显示 IP/QR。
- 打包 Electron/Tauri 给非技术房主；MVP 可先用命令行。

## 5. 玩家小程序

### 5.1 页面变化

| 页面 | 变化 |
|---|---|
| 首页 | “加入房间”为主；“创建房间”只做提示 |
| 创建房间 | iOS：提示“请用非 iPhone 设备开房”；Android：提示“请打开 Monopay Host App 开房” |
| 加入房间 | 扫码/输 IP + 房号；昵称/头像 |
| 大厅 | 玩家列表、房主开始 |
| 账房 | 余额、付款、流水 |
| 银行 | 仅 Host App 有；小程序玩家看不到 |
| 结算 | 资产/负债、排名 |

### 5.2 TCP 客户端

```text
connect(ip, port):
  socket = wx.createTCPSocket()
  socket.connect({ address: ip, port })
  socket.onConnect -> send hello/join
  socket.onMessage -> parse NDJSON -> dispatch
  socket.onClose/onError -> retry with backoff
```

- 连接超时 5s；重试 3 次；失败提示“连不上房主，请确认同一 Wi-Fi/热点”。
- 心跳 10s；30s 无 pong 视为断线。
- 重连带 `playerToken` + `lastSeq`；Host 返回缺失事件或 snapshot。
- 所有请求带 `clientRequestId`；重试复用，避免重复扣款。

### 5.3 扫码/输 IP

- Host 二维码内容：`tcp://192.168.43.1:3000?room=ABC123`。
- 小程序 `wx.scanCode({ scanType:['qrCode'] })` 解析。
- 也支持手动输入 IP/端口/房号；记住上次 host。
- 二维码不是小程序码；玩家必须先打开小程序，再在小程序内扫码。
- 如果玩家用微信“扫一扫”直接扫，只会看到文本；所以入口要写清楚“打开小程序 → 扫码加入”。

### 5.4 iPhone 限制

- 创建房间页检测 `wx.getSystemInfoSync().platform === 'ios'`：
  - 显示“iPhone 不能当房主，请用 Android/平板/笔记本开房”。
  - 提供“如何开房”说明；不提供创建按钮。
- iPhone 可以正常加入、付款、结算。
- Android 创建页：提示“请打开 Monopay Host App”；如果未安装，给出下载/安装说明（Host App 通过 APK/文件分发，不走小程序审核）。

## 6. 协议

### 6.1 帧格式

- TCP 长连接；UTF-8；**NDJSON**：一行一个 JSON，`\n` 分隔。
- 单条消息上限 64KB；超过断开。
- 心跳：`{"type":"ping"}` / `{"type":"pong"}`。

### 6.2 消息

客户端 → Host：

```json
{ "id": "req-1", "type": "hello", "payload": { "roomCode": "ABC123", "playerToken": "...", "lastSeq": 12 } }
{ "id": "req-2", "type": "action", "action": "playerPay", "payload": { "...": "..." }, "clientRequestId": "uuid" }
{ "id": "req-3", "type": "snapshot", "payload": { "sinceSeq": 12 } }
```

Host → 客户端：

```json
{ "id": "req-1", "type": "ack", "payload": { "playerId": "p_1", "room": { "...": "..." }, "players": [], "transactions": [] } }
{ "id": "req-2", "type": "ack", "payload": { "transaction": { "...": "..." }, "balances": {} } }
{ "type": "event", "seq": 13, "event": { "type": "transaction", "transaction": { "...": "..." } } }
{ "id": "req-2", "type": "error", "error": { "code": "INSUFFICIENT_BALANCE", "message": "余额不足" } }
```

### 6.3 动作

| action | 调用者 | 说明 |
|---|---|---|
| `join` | 玩家 | 房号 + token + 昵称；Host 分配 playerId |
| `snapshot` | 玩家 | 房间/玩家/最近流水；可带 `sinceSeq` |
| `playerPay` | 玩家 | 玩家→玩家/银行；余额校验 |
| `refund` | 原收款方 | 全额反向；终态 |
| `submitAssets` | 玩家 | 结算中填资产/负债 |
| `listTransactions` | 玩家 | 分页 |
| `logEvent` | 玩家 | 试玩分析（可选） |

Host App 内部（不经过 TCP）：

- `createRoom` / `startGame` / `endGame` / `bankPay` / `paySalary` / `bankCollect` / `reverse` / `markBankrupt` / `confirmSettlement` / `resumeGame` / `dissolve`。
- Host 作为玩家时，Host UI 也走同一套用例。

### 6.4 事件

- `event.type`：`transaction` / `roomState` / `playerUpdate` / `settlement` / `kick`。
- 每个事件带 `seq`；客户端按 `seq` 去重/排序。
- 收款人判断 `event.transaction.toPlayerId === me.playerId` 才响；其他静默。
- 退款 event 的 `toPlayerId` 是原付款人；原付款人响，退款发起人不响。
- 开局资金不发 event（避免 6 连响）；玩家进房看余额。
- 冲正默认不发 sound event；以流水为准。

### 6.5 错误码

复用 v1：`INVALID_ARGUMENT` / `ROOM_NOT_FOUND` / `ROOM_FULL` / `ROOM_STATE` / `FORBIDDEN` / `INSUFFICIENT_BALANCE` / `DUPLICATE_REQUEST` / `NOT_REFUNDABLE` / `ALREADY_TERMINAL` / `NOT_SETTLING` / `ALREADY_SETTLED` / `RATE_LIMITED` / `INTERNAL`。

## 7. 数据模型（SQLite）

```sql
rooms (
  id TEXT PRIMARY KEY,
  code TEXT UNIQUE,
  status TEXT,              -- waiting/playing/settling/settled
  host_identity TEXT,       -- bank_only/dual
  config_json TEXT,
  seq INTEGER DEFAULT 0,
  created_at INTEGER, started_at INTEGER, ended_at INTEGER,
  settling_at INTEGER, settled_at INTEGER, dissolved_at INTEGER
)

players (
  id TEXT PRIMARY KEY,
  room_id TEXT,
  token TEXT UNIQUE,        -- 客户端 token；不用 openid
  nickname TEXT, avatar TEXT,
  is_player INTEGER, is_banker INTEGER,
  balance INTEGER,
  status TEXT,              -- active/bankrupt/left
  bankrupt_at INTEGER,
  joined_at INTEGER
)

transactions (
  id TEXT PRIMARY KEY,
  room_id TEXT,
  seq INTEGER,
  from_type TEXT, from_player_id TEXT,
  to_type TEXT, to_player_id TEXT,
  amount INTEGER,
  balance_after_from INTEGER,
  balance_after_to INTEGER,
  category TEXT, note TEXT, source TEXT,
  status TEXT,              -- success/refunded/reversed
  reversal_of TEXT, refund_of TEXT,
  operator_id TEXT,
  client_request_id TEXT,
  created_at INTEGER,
  UNIQUE(room_id, client_request_id),
  UNIQUE(room_id, seq)
)

asset_snapshots (
  room_id TEXT, player_id TEXT,
  property_value INTEGER, debt INTEGER, note TEXT,
  updated_at INTEGER,
  PRIMARY KEY(room_id, player_id)
)

settlements (
  id TEXT PRIMARY KEY, room_id TEXT UNIQUE,
  rankings_json TEXT, created_at INTEGER
)

room_events (
  id TEXT PRIMARY KEY, room_id TEXT,
  type TEXT, actor_id TEXT, payload_json TEXT, created_at INTEGER
)
```

- SQLite：单写者；`BEGIN IMMEDIATE`；WAL；每个写操作一个事务。
- 金额整数 M；不允许负余额；余额校验在事务内。
- 数据备份：Host App 导出 JSON/SQLite 文件；换机/重装。
- 数据清理：房间结束/解散后保留 24h；Host 可手动删除。

## 8. 网络与加入

### 8.1 房主热点

- 房主手动开热点；Host App 显示提示和当前 IP。
- 玩家连热点 → 打开小程序 → 扫码/输 IP。
- Android 热点常见网段 `192.168.43.x`；不同厂商不同；Host App 读取并显示。
- 热点可能开 AP 隔离；如果玩家连不上，先检查热点设置/换路由器。

### 8.2 同一 Wi-Fi

- 所有人在同一个路由器下；关闭 AP 隔离；Host 防火墙放行端口。
- 公共 Wi-Fi/酒店 Wi-Fi 可能隔离客户端；不保证可用。
- 房主 IP 可能变化；二维码每次开房重新生成。

### 8.3 二维码

```text
tcp://192.168.43.1:3000?room=ABC123
```

- Host App 显示二维码 + 明文 IP/端口/房号。
- 玩家在小程序内 `wx.scanCode` 扫码；或手动输入。
- 不要把二维码做成小程序码；没有云，小程序码不能带房间参数。

## 9. 安全

- 仅局域网；不暴露公网；不要在公共 Wi-Fi 开房。
- 房号 + `playerToken`；Host 可要求“加入需房主确认”。
- Host App 显示已连接玩家，可踢人/拉黑。
- 输入校验：金额整数、类别枚举、备注 50 字、消息大小上限。
- 无限流：单连接消息频率限制；防刷。
- 不做 TLS；局域网内明文；不要传输手机号/位置/真钱信息。
- 数据在 Host 设备；Host 负责备份/删除。
- 小程序审核：LAN TCP 可能被问；准备“本地桌游记账工具”的说明；如果审核不通过，回退浏览器/云。

## 10. 失败与恢复

| 场景 | 表现 | 处理 |
|---|---|---|
| 房主 Host App 退出/被杀 | 所有玩家断线 | 提示“房主服务已停止”；Host 重开后恢复 SQLite，玩家重连 |
| 房主设备休眠 | 连接超时 | 前台服务 + 唤醒锁 + 充电；系统设置引导 |
| 玩家切后台/锁屏 | TCP 可能断开 | 回前台重连；带 `lastSeq` 拉缺失事件 |
| 热点/路由器 AP 隔离 | 连不上 Host | 提示检查 AP 隔离/换 Wi-Fi |
| IP 变化 | 旧二维码失效 | Host 重新生成二维码；玩家重扫 |
| Host 崩溃 | 当前事务可能丢失 | SQLite 事务保证已提交数据；未提交的付款让玩家重试 |
| 数据丢失 | 换机/卸载 | 定期导出备份；Host UI 提供导出 |
| 小程序审核不通过 | 无法发布 | 回退浏览器玩家端或云开发 |

## 11. 里程碑

| 阶段 | 内容 | 产出 | 估时 |
|---|---|---|---|
| **Gate 0** | LAN TCP spike | 笔记本 Node TCP + 最小小程序；iOS/Android 真机连接/收发/重连/6 客户端 | 1–2 天 |
| **M0** | 协议 + 桌面 Host | NDJSON 协议、SQLite、create/join/start/snapshot、二维码 | 1 周 |
| **M1** | 玩家小程序 | 扫码/输 IP、连接、大厅、付款、流水、重连 | 1–2 周 |
| **M2** | 银行/纠错/结算 | 工资、退款、冲正、破产、结算中/确认、导出 | 2 周 |
| **M3** | Android Host | Kotlin Host App、前台服务、热点引导、QR、SQLite | 3–4 周 |
| **M4** | 硬化/试玩 | 6 人并发、断线、电量、AP 隔离、试玩修复 | 2 周 |

**总计：约 8–12 周**（桌面 Host 先行；Android Host 是最大变量）。

如果 Gate 0 不通过：

- 回退浏览器玩家端：Host 提供 HTTP/WS；玩家扫码打开网页；约 4–6 周。
- 或回退云开发小程序：约 5–8 周；每月 20–70 元。

## 13. Gate 0 spike 清单

## 14. 回退方案

| 回退 | 适用 | 代价 |
|---|---|---|
| **浏览器玩家端** | 小程序 LAN TCP 不可用/审核不过 | Host 提供 HTTP/WS；玩家扫码开网页；约 4–6 周；无小程序 |
| **云开发小程序** | 需要 iPhone host/远程/稳定 | 约 5–8 周；20–70 元/月 |
| **单手机共享账本** | 无网络/极简 | 1–2 周；一台手机轮流传 |
| **原生 P2P App** | 必须无云+离线+跨平台 | 2–3 个月；不是小程序 |

## 15. 产品变更（相对 v1.0 云开发版）

- 房间：云开发房间 → **房主 Host App 本地房间**。
- 创建：小程序创建 → **Host App 创建**；小程序创建页只做提示。
- 加入：小程序码/房号 → **扫码（tcp://IP:port?room=CODE）/手动输 IP + 房号**。
- 身份：微信 openid → **本地 playerToken**；Host App 用 hostToken。
- 数据：云数据库 → **Host 设备 SQLite**；Host 负责备份/删除。
- 实时：云 watch → **TCP 事件**。
- 房主掉线：银行付款暂停 → **Host App 停止 = 全场暂停**；恢复后重连。
- iPhone：可加入，**不能开房**；创建页提示换非 iPhone。
- 成本：20–70 元/月 → **0 云费**；代价是 Host 设备/热点/电量。
- 规则：角色、付款、退款、冲正、结算规则**不变**。

## 16. 结论

这条路能满足“手机组局、零云费、房主设备当服务器”，但有三个硬门槛：

1. `wx.createTCPSocket` 真机可用；
2. 小程序审核接受 LAN TCP；
3. 房主设备能长期跑 Host App（Android/平板/笔记本）。

**先做 Gate 0，再决定是否全量开发。** 如果 Gate 0 不过，浏览器玩家端是最稳的零云回退；云开发是最稳的产品回退。
