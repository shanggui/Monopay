# Monopay 实现与部署方案

> [!WARNING]
> 本文档记录初始实现方案。当前部署已改为 **app-only Compose + 现有反向代理**：
> Caddy、Vant、Tailwind 均已移除。实际部署以 [README](../README.md) 和
> [部署运行手册](部署运行手册.md) 为准；下文的 Caddy 段落仅作历史记录。

> 版本：v1.0 ｜ 日期：2026-11-02 ｜ 对应技术路线 v3.0
>
> 目标：用最少工具把项目搭起来，并形成 **GitHub Actions → GHCR 镜像 → 服务器 Docker Compose 一键部署** 的闭环。

---

## 0. 结论

1. **不需要“全栈脚手架”或 Nx/Turborepo。** 用 `pnpm workspace` + 官方 `create-vite` 生成前端；后端手写一个最小 Fastify 工程即可。
2. **一个 Docker 镜像**同时包含 Fastify API、WebSocket 和构建后的 Vue 静态文件；TLS 由服务器现有反向代理终止。
3. GitHub Actions 把镜像推到 **GHCR（GitHub Container Registry）**，镜像地址是 `ghcr.io/<owner>/monopay:<tag>`。
4. 服务器只需要 `compose.yaml`、`.env` 和 Docker，执行 `docker compose pull && docker compose up -d` 即可。
5. 当前 Windows 开发机没装 Docker **不影响**：镜像由 GitHub Actions 构建；本地只用 `pnpm dev` 开发。

## 1. 初始化用什么工具

| 用途 | 选择 | 说明 |
|---|---|---|
| 前端生成 | `pnpm create vite` | 官方 Vite 脚手架，选 `vue-ts`；比 `create-vue` 更干净 |
| 后端生成 | 手写 | Fastify 不需要生成器；`fastify-cli` 的目录结构反而要改 |
| Monorepo | pnpm workspace | 2 个 app + 2 个 package，Turborepo/Nx 暂无收益 |
| 前端 | Vue 3 + Vite + TypeScript | 已定 |
| UI | Vant 4 + Tailwind CSS | Vant 只取行为组件，皮肤全部自定义 |
| 动效 | CSS transition + Motion One | 页面转场/成功动画；不引入重型动画库 |
| 图标 | Lucide | 统一线性图标，避免金币/筹码符号 |
| 后端 | Fastify 5 + TypeScript | REST + `@fastify/websocket` |
| 校验 | Zod | 前后端共享 schema |
| 数据库 | SQLite + Drizzle ORM | MVP 单进程足够；迁移用 Drizzle Kit |
| 测试 | Vitest + Fastify inject + Playwright | 账本规则、API、E2E |
| 构建 | Vite（Web）+ tsup（Server） | Server 打成单文件，workspace 包一起 bundle |
| 部署 | Docker Compose + 现有反向代理 | 一键、HTTPS 在反代终止 |
| 镜像仓库 | GHCR | GitHub 原生，和仓库/ Actions 同一套权限 |

**不需要**：NestJS、Prisma、Kubernetes、Redis、独立前端容器、额外 TLS 容器。

## 3. 初始化命令

### 3.1 根工程

```bash
mkdir monopay && cd monopay
pnpm init
```

`pnpm-workspace.yaml`：

```yaml
packages:
  - apps/*
  - packages/*
```

根 `package.json` 至少包含：

```json
{
  "name": "monopay",
  "private": true,
  "packageManager": "pnpm@12.14.0",
  "scripts": {
    "dev": "pnpm -r --parallel dev",
    "build": "pnpm -r build",
    "test": "pnpm -r test",
    "lint": "pnpm -r lint",
    "typecheck": "pnpm -r typecheck"
  }
}
```

### 3.2 前端

```bash
pnpm create vite apps/web --template vue-ts
```

把 `apps/web/package.json` 的 `name` 改成 `@monopay/web`，然后：

```bash
pnpm --filter @monopay/web add vue-router pinia vant lucide-vue-next motion
pnpm --filter @monopay/web add -D tailwindcss @tailwindcss/vite unplugin-vue-components
```

- Tailwind 4 用 `@tailwindcss/vite`；Vant 的 reset 和 Tailwind preflight 可能冲突，**只引入 theme + utilities，不引入 preflight**。
- Vant 按需引入用 `unplugin-vue-components` + `VantResolver`。
- 所有颜色走 CSS 变量，Tailwind 里用 `var(--...)` 或 `@theme` 映射，不要把十六进制写死在组件里。

### 3.3 后端

```bash
mkdir apps/server
cd apps/server
pnpm init
pnpm add fastify @fastify/websocket @fastify/static @fastify/helmet @fastify/rate-limit zod drizzle-orm better-sqlite3
pnpm add -D typescript tsx tsup drizzle-kit @types/node @types/better-sqlite3 vitest
```

`apps/server/package.json` 关键字段：

```json
{
  "name": "@monopay/server",
  "type": "module",
  "scripts": {
    "dev": "tsx watch src/index.ts",
    "build": "tsup",
    "start": "node dist/index.js",
    "db:generate": "drizzle-kit generate",
    "test": "vitest run",
    "typecheck": "tsc --noEmit"
  }
}
```

`tsup.config.ts`：

```ts
import { defineConfig } from 'tsup'

export default defineConfig({
  entry: ['src/index.ts'],
  format: ['esm'],
  target: 'node24',
  outDir: 'dist',
  clean: true,
  sourcemap: true,
  // 只把 workspace 包打进去，Fastify 等仍走 node_modules
  noExternal: [/^@monopay\//],
})
```

> 这样 `packages/shared` 和 `packages/ledger-core` 不需要单独构建；Vite/tsup 直接消费 TS 源码。

### 3.4 共享包

`packages/shared/package.json`：

```json
{
  "name": "@monopay/shared",
  "type": "module",
  "main": "src/index.ts",
  "types": "src/index.ts"
}
```

`packages/ledger-core/package.json` 同理。两个包都只写纯 TS，不依赖 Fastify、Vue 或数据库。

## 4. 先做 M0“能部署的空壳”

不要先写完整业务。先按这个顺序打通部署链路：

1. `GET /healthz` 返回 `{ ok: true }`。
2. Web 首页能请求 `/healthz` 并显示“服务正常”。
3. SQLite 能启动、迁移能跑、`/data` 能写。
4. 本地 `pnpm build` 成功。
5. GitHub Actions 能推出 `ghcr.io/<owner>/monopay:sha-...`。
6. 服务器能 `docker compose up -d`，HTTPS 能打开。
7. 再开始房间、付款、账本。

M0 验收通过后，后面每个功能都能持续部署，不会到最后才发现 Docker/HTTPS/静态文件有问题。

## 5. Docker 镜像

### 5.1 设计

- **一个 app 容器**：Fastify 监听 `3000`，同时提供 `/api`、`/ws` 和 SPA 静态文件。
- **一个 Caddy 容器**：监听 `80/443`，自动申请证书，反代到 `app:3000`。
- SQLite 文件挂载到宿主机 `./data`。
- 容器用非 root 的 `node` 用户（UID 1000）。
- 启动时跑 Drizzle 迁移；迁移失败则容器不健康，Caddy 不会接流量。

### 5.2 Dockerfile

```dockerfile
# syntax=docker/dockerfile:1.7

FROM node:24-bookworm-slim AS base
ENV PNPM_HOME=/pnpm
ENV PATH=$PNPM_HOME:$PATH
RUN corepack enable
WORKDIR /app

FROM base AS deps
# better-sqlite3 没有预编译包时需要
RUN apt-get update \
 && apt-get install -y --no-install-recommends python3 make g++ \
 && rm -rf /var/lib/apt/lists/*
COPY package.json pnpm-lock.yaml pnpm-workspace.yaml .npmrc ./
COPY apps/web/package.json apps/web/package.json
COPY apps/server/package.json apps/server/package.json
COPY packages/shared/package.json packages/shared/package.json
COPY packages/ledger-core/package.json packages/ledger-core/package.json
RUN --mount=type=cache,id=pnpm,target=/pnpm/store \
    pnpm install --frozen-lockfile

FROM deps AS build
COPY . .
RUN pnpm --filter @monopay/web build \
 && pnpm --filter @monopay/server build \
 && pnpm --filter @monopay/server deploy --prod /out/server

FROM node:24-bookworm-slim AS runner
ENV NODE_ENV=production
ENV PORT=3000
ENV DB_PATH=/data/monopay.db
ENV WEB_DIST=/app/web
WORKDIR /app
RUN mkdir -p /data && chown -R node:node /data
COPY --from=build --chown=node:node /out/server ./
COPY --from=build --chown=node:node /app/apps/web/dist /app/web
USER node
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=5s --start-period=20s --retries=3 \
  CMD node -e "fetch('http://127.0.0.1:3000/healthz').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"
CMD ["node", "dist/index.js"]
```

配套 `.npmrc`：

```ini
inject-workspace-packages=true
```

> `pnpm deploy` 需要这个设置，才能把 workspace 依赖装进独立目录。若以后换 npm，可改成“复制整个 workspace + `npm ci --omit=dev`”的多阶段方案。

### 5.3 `.dockerignore`

```text
node_modules
**/node_modules
**/dist
.git
.github
docs
data
*.png
```

## 6. 服务器一键部署

### 6.1 `deploy/compose.yaml`

```yaml
name: monopay

services:
  app:
    image: ghcr.io/OWNER/monopay:${MONOPAY_TAG:-latest}
    restart: unless-stopped
    environment:
      PUBLIC_URL: ${PUBLIC_URL}
      DB_PATH: /data/monopay.db
      TRUST_PROXY: "true"
    volumes:
      - ./data:/data
    expose:
      - "3000"
    healthcheck:
      test:
        - CMD
        - node
        - -e
        - "fetch('http://127.0.0.1:3000/healthz').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 20s

  caddy:
    image: caddy:2-alpine
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    environment:
      DOMAIN: ${DOMAIN}
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      app:
        condition: service_healthy

volumes:
  caddy_data:
  caddy_config:
```

### 6.2 `.env`

```dotenv
DOMAIN=monopay.example.com
PUBLIC_URL=https://monopay.example.com
MONOPAY_TAG=v0.1.0
```

> 生产环境建议固定版本 tag，不要用 `latest`；回滚就是改 `MONOPAY_TAG` 再 `up -d`。

### 6.3 `deploy/Caddyfile`（历史方案，已移除）

```text
{$DOMAIN} {
  encode zstd gzip
  reverse_proxy app:3000
}
```

Caddy 会自动处理 WebSocket Upgrade；不需要额外配置。

### 6.4 首次部署

```bash
# 服务器上，只需要 Docker Engine + Compose plugin
mkdir -p /opt/monopay/data
cd /opt/monopay

# 放入 compose.yaml、Caddyfile、.env
sudo chown -R 1000:1000 data

docker compose pull
docker compose up -d
docker compose ps
```

打开 `https://monopay.example.com/healthz` 验证。

**权限是“一键部署”最容易翻车的地方**：镜像以 UID 1000 运行，宿主机 `./data` 必须可写；上面的 `chown` 不能省。

### 6.5 更新与回滚

```bash
# 更新
docker compose pull
docker compose up -d

# 回滚：把 .env 的 MONOPAY_TAG 改回旧版本
docker compose pull
docker compose up -d
```

### 6.6 服务器已有 Nginx / 80、443 被占用

不要启动 Caddy，改成：

```yaml
services:
  app:
    image: ghcr.io/OWNER/monopay:${MONOPAY_TAG:-latest}
    restart: unless-stopped
    environment:
      PUBLIC_URL: ${PUBLIC_URL}
      DB_PATH: /data/monopay.db
      TRUST_PROXY: "true"
    volumes:
      - ./data:/data
    ports:
      - "127.0.0.1:3000:3000"
```

现有 Nginx 加反代：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
}
```

## 7. GitHub → GHCR

### 7.1 先理解“package”

这里的 package 不是 npm 包，而是 **OCI 容器镜像**：

```text
ghcr.io/<owner>/monopay:<tag>
```

GHCR 是 GitHub 自带的容器仓库。推到 GHCR 后，任何机器都能：

```bash
docker pull ghcr.io/<owner>/monopay:v0.1.0
```

### 7.2 工作流

`.github/workflows/docker-publish.yml`：

```yaml
name: publish-image

on:
  push:
    branches: [main]
    tags: ["v*"]
  workflow_dispatch:

permissions:
  contents: read
  packages: write

jobs:
  docker:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: docker/setup-buildx-action@v3

      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Lowercase image name
        run: echo "IMAGE=ghcr.io/${GITHUB_REPOSITORY_OWNER,,}/monopay" >> "$GITHUB_ENV"

      - id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.IMAGE }}
          tags: |
            type=ref,event=branch
            type=semver,pattern={{version}}
            type=semver,pattern={{major}}.{{minor}}
            type=sha,prefix=sha-
            type=raw,value=latest,enable={{is_default_branch}}

      - uses: docker/build-push-action@v6
        with:
          context: .
          platforms: linux/amd64
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
```

说明：

- `GITHUB_TOKEN` 自带 `packages: write`，不需要手动建 PAT。
- GHCR 镜像名必须小写；`Lowercase image name` 这一步处理 owner 大小写。
- `main` 推送 → `main` + `sha-xxx` + `latest`；打 `v0.1.0` tag → `0.1.0`、`0.1`、`sha-xxx`。
- 只有 `linux/amd64`；如果服务器是 ARM（如 Oracle ARM、树莓派），再加：

```yaml
      - uses: docker/setup-qemu-action@v3
      # build-push-action 的 platforms 改成：
      # platforms: linux/amd64,linux/arm64
```

多架构会明显变慢，MVP 先单架构。

### 7.3 第一次发布

```bash
git add .
git commit -m "chore: add docker image pipeline"
git push origin main
```

等 Actions 变绿，在仓库右侧 **Packages** 里能看到 `monopay`。然后：

1. 打开 package 页面 → **Package settings**。
2. 最下方 **Danger Zone** → **Change visibility** → **Public**。
3. 之后不用登录就能 `docker pull`。

如果保持 Private，服务器需要：

```bash
echo "$GHCR_PAT" | docker login ghcr.io -u <owner> --password-stdin
```

PAT 用 classic token，勾选 `read:packages`。

### 7.4 打版本 tag

```bash
git tag v0.1.0
git push origin v0.1.0
```

Actions 会推出：

```text
ghcr.io/<owner>/monopay:0.1.0
ghcr.io/<owner>/monopay:0.1
ghcr.io/<owner>/monopay:sha-xxxxxxx
```

生产 compose 固定 `MONOPAY_TAG=0.1.0`。

### 7.5 常见 403

- 仓库 **Settings → Actions → General → Workflow permissions** 设为 Read and write。
- 组织设置了 package 创建限制：到组织 Settings → Packages 允许 Actions 创建。
- package 已存在但仓库没有写权限：Package settings → Manage Actions access → 给当前仓库 Write。

## 8. 完整发布链路

```text
本地 pnpm dev
   │
   ├─ push main / tag v0.1.0
   ▼
GitHub Actions
   ├─ checkout
   ├─ buildx
   ├─ docker build
   └─ push ghcr.io/<owner>/monopay:<tag>
          │
          ▼
服务器 /opt/monopay
   ├─ docker compose pull
   ├─ docker compose up -d
   ├─ Caddy 自动 HTTPS
   └─ app: Fastify + SQLite + SPA
```

## 9. 需要确认的服务器信息

这些会影响 compose 和 workflow 的最终写法：

1. 服务器 CPU 架构：`amd64` 还是 `arm64`？
2. 80/443 是否空闲？是否已有 Nginx/Caddy？
3. 是否有域名，DNS 能否指向服务器？
4. GHCR 镜像要 Public 还是 Private？
5. GitHub 仓库 owner/repo 名称（决定镜像地址）。
6. SQLite 是否够用，还是已有 Postgres？

默认按 **amd64 + 80/443 空闲 + Caddy + Public GHCR + SQLite** 写；不符合再改。
